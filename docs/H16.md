# H16 — le même corpus à travers saknussemm lui-même, et la différence avec mes scripts

Jusqu'ici toutes les campagnes appelaient Mistral directement, à découpage
fixe, pour observer le modèle brut. Ce rapport fait passer les 9 pages
d'OCR17+ **dans saknussemm** (branche `garde-attachement-et-producteur-
composite`, PR #166), six bras, même modèle (`medium`), et regarde ce que
le pipeline fait que mes scripts ne faisaient pas : valider, retenter,
redescendre, tenir les trois étages de garde, les passes document-wide.
Outil : `tools/run_saknussemm_ocr17.py`.

## Ce qui se recoupe, ce qui diverge

**Le zéro du proxy tient dans la vraie chaîne** — six bras, 0 ligne mal rattachée au sens du proxy (relue à l'œil en H19 : un mot de la ligne suivante en tête de Corneille tl_7, sorti en `review_required`),
et `closer_to_another_line` a refusé trois lignes que la portée voisine
n'aurait pas vues (le même trio dans les deux bras à portée page ; les
jumelles à 0,85 n'en exemptent aucune, leurs sources se ressemblant à
~0,75).

**Le recadrage par ligne donne le même chiffre des deux côtés** : 6,74 %
dans saknussemm, 6,4 % chez moi. La différence, 0,3 point, ce sont les
**replis de césure** (`hyphen_pair_fallback`, 13 à 18 lignes par bras —
5 à 7 % des lignes) : saknussemm refuse toute paire de césure dont un
membre a bougé de travers, et mes scripts n'avaient aucune notion de
césure. C'est un prix de sûreté que mes chiffres ne payaient pas.

**Le gain de la page entière n'est pas reproduit — et il ne peut pas
l'être avec ce que la branche livre.** Mon meilleur bras (4,58 %) donnait
au modèle l'**image de la page entière** ; dans saknussemm, ni
`VisionEditProducer` (un recadrage par ligne) ni le composite (une bande de
recadrages) ne la lui donnent. Le composite a été construit pour
l'**identité**, pas pour le contexte ; sur OCR17+ l'identité ne se perdait
pas, donc il n'apporte que le coût d'appel. Le levier de qualité mesuré en
H10 — le contexte visuel de la page — n'a toujours pas de producteur dans
saknussemm.

**Le planificateur suit les régions PAGE.** Avec
`max_lines_per_request=20`, une page de 42 lignes descend à la granularité
BLOCK, et BLOCK fait **un chunk par groupe de régions**, sans jamais
regrouper les petites : Corneille, 32 chunks ; Molière, 29 ; 105 pour 251
lignes. Mes bandes de 20 rangées avaient 2 à 3 rangées. Un producteur qui
veut du contexte a besoin d'un découpage par **fenêtre**, que le
planificateur n'offre qu'en descente.

**Le prompt générique de `page_aligned` modernise le XVIIe.** 10,96 %,
pire que ne rien faire : `meritay-je` → `mériterais-je`, `ie` → `je`,
`vn` → `un`, `tempefie` → `tempête`, malgré la règle « ne modernise pas ».
Une règle de plus nommant l'époque et le ſ long ramène à 6,71 % — et le
modèle **rétablit** des ſ que l'OCR n'avait pas (source 0, VT 274) depuis
sa connaissance de la typographie. Le prompt n'est pas un détail de
campagne ; sur ce corpus il vaut 4 points, dans les deux sens.

**Un défaut réel trouvé par le pipeline, invisible à mes scripts.** Sous
`line_matching="characters"`, un U+2028 dans une ligne rendue a fait
refuser la page par le validateur (« contains a line separator »), retenter
quatre fois, redescendre PAGE → BLOCK, et finir en `all_attempts_exhausted`
sur les 19 lignes de Balzac. Sous Jaccard la même ligne était simplement
refusée. Corrigé sur la branche (`_one_line`, deux tests) : la ligne est
aplatie avant l'appariement. Mes scripts recollaient ce séparateur sans
rien dire.

**Une capacité qui doit être déclarée.** `VisionEditProducer` sans
`max_images` a envoyé 19 recadrages ; Mistral en refuse 9, le pipeline
retente et redescend au lieu de découper. La démo déclare
`ModelCapabilities(max_images=8)` ; le run l'a fait aussi à partir du
second essai. Un défaut de configuration, pas de code — mais un défaut
silencieux si l'on ne lit pas les événements.

## Ce que ça change pour la préconisation

1. Le veto par marge et le producteur composite **tiennent dans la vraie
   chaîne** : zéro partout, retries et replis lisibles au rapport.
2. **Le prompt par corpus est obligatoire**, pas optionnel : sans lui,
   `page_aligned` fait pire que rien sur le cœur de cible.
3. **Le producteur page entière reste à écrire** — c'est lui qui porte le
   gain de 4 points, et rien dans saknussemm ne le donne encore. Avec les
   identifiants dans le texte et la page en image, il est exactement le bras
   de H12 §6 : 4,58 %, zéro.
4. Un producteur vision veut un découpage par **fenêtre de N lignes**, pas
   par région ; à exposer sur le planificateur avant de mesurer le composite
   à sa vraie taille.
5. Les replis de césure (5–7 % des lignes) sont un prix que mes mesures
   ignoraient ; il est réel et il est sûr.

## 4. Vague VR — sept défauts, sept clôtures, vérifiées par run

Chaque défaut vu ci-dessus est devenu un item du plan de saknussemm
(`docs/PLAN.md`, vague `VR`) et chaque item qui change ce que le modèle
voit ou ce que le garde accepte a été vérifié par un run sur les mêmes neuf
pages.

| item | correctif | vérification |
|---|---|---|
| VR-1 pas de producteur page entière | `PageVisionEditProducer` | 5,74–6,29 % sans note ; **4,19 %** avec |
| VR-2 un chunk par région | `ChunkPlannerConfig(coalesce_blocks=True)` | 105 → 16 chunks, jetons ÷ 2, 4,23 % avec note |
| VR-3 plafond d'images non déclaré | lu sur le client (`MAX_IMAGES_PER_CALL`) | test unitaire |
| VR-4 prompt générique qui modernise | `with_corpus_notes`, `CORPUS_NOTE_EARLY_MODERN_FRENCH` | texte 10,96 → 6,71 % ; vision 6,29 → 4,39 % |
| VR-5 séparateur de ligne | `_one_line` | retries 4 → 0, descente 1 → 0 |
| VR-6 coût des replis de césure | mesure | 21 lignes, 0,4 point |
| VR-7 plancher 0,15 + portée page | mesure | 0 mal rattachée au proxy (1 mot d'une voisine à l'œil, H19), 4,19 % — décision de mainteneur |

**Ce que la boucle a appris sur la différence script / pipeline.** Sans
la note de corpus, aucun producteur de saknussemm n'atteignait le chiffre
du script (4,58 %) ; avec elle, tous le dépassent. L'écart n'était donc ni
dans les gardes (qui n'ont refusé que des lignes justes à refuser) ni dans
les retries (aucun), mais dans **une phrase du prompt** que mes scripts
portaient et que la bibliothèque ne portait pas — plus les replis de
césure, 0,4 point, prix de sûreté réel. Le composite regroupé lit ici
aussi bien que la page entière (4,23 contre 4,19–4,39 %) pour deux fois
plus d'appels ; la page entière reste le producteur de référence sur les
pages à une colonne.
